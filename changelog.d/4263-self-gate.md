### Added

- `autospec_core::self_gate`: self-gating of gatekeeping automation (issue #4263). Encodes the incident's rules as checkable primitives: `gate_destructive_run` (a destructive script without a dry-run mode is refused, and the first production run is refused until a dry run has been performed — a dry run is never refused); `SelectionReport` (a selection predicate reports "N of M selected" — the denominator is never optional, a numerator above the denominator is a counting bug, and a report not written to a reviewable file is a finding); `AutomationArtifact` (an automation that decides work needs a file, a comment per condition explaining the bug it encodes, and one fixture test); `select_reaps` with `ReapCandidate` / `ReapPlan` (destructive reaping is capped — a zero cap is an error, not a silent pass — and selects by severity, never by listing order, naming every deferred offender, because queue order under a cap starves exactly the offenders it was meant to reach); `trust_verdict` with `ReliabilityEvidence` (only `Gated` is trust evidence; `RanRecently { times }` is not, at any count); `AttemptLedger` ("attempted" keys on the patch, not the issue — a new patch for an attempted issue is still a candidate, and `selector_line` reports "attempted N of M patches (K issues)" so a unit mix-up is visible in the line itself); and `WorkState` (a directory is created when an agent starts; only `HasPatch` is a conversion candidate — `InProgress` and `Converted` are not). Tests: `crates/autospec-core/tests/self_gate.rs`.
