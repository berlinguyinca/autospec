### Added

- `autospec review-quorum` and `autospec_core::autonomous::review_quorum`: a post-PR review quorum bound to the exact current head SHA and review target, with blocks processed first (never dropped), digest format + binding checks, `reviewer_groups`, bot-alias and case normalisation, and a shared conformance vector file also loaded by herdr-engineering. `publish` posts a verdict to Herdr as a `reviewed` edge with the reviewer's own key; `request` runs the configured review dispatch once per (PR, head) when Herdr reports `rereview_required`; `--write-report` feeds `autospec-promote-pr.sh` (Herdr federated workbench T06). No shell lines added.
- `review-quorum verify-report` binds `review-quorum.json` to the live PR head and target, and `--write-report` overwrites the report with a non-pass one on any evaluation error, so `autospec-promote-pr.sh` can no longer promote a stale or missing required quorum (one script line replaced, shell count unchanged); `request` dedupe is serialised by a lock with pending/dispatched/failed markers; `publish --retract`; URL, pr-node and receipt validation; key files in a private temp dir; ASCII-only matching shared with Herdr.
- Round 3: the requirement to gate comes only from trusted config (operator file, default branch), never the PR checkout; optional HMAC attestation of the report (`review_quorum.attestation_key_file`), a freshness bound (`max_report_age_seconds`, default 900), a live Herdr re-check when the operator enabled Herdr, symlink refusal, `--head` for later steps, a real YAML parser; `request` markers are MAC-authenticated in an operator-owned state dir with backoff and a kill-on-timeout dispatch.
