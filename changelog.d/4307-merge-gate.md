### Added

- `autospec_core::merge_gate`: merge-gate invariants for the patch-to-PR converter (issue #4307). The converter's local gate (fmt / build / clippy / test on one host) covered three of the six jobs the repository's `rust-suites` CI runs, so a macOS-gated test file (#4306) with five compile errors sat merged and hidden while the workflow's pass rate on `main` was 0/40 — a red gate read as a green one. The module makes the four invariants checkable: (1) the converter's merge requires the real CI gate — `decide(GateResult, CiStatus, BaseBranchStatus) -> MergeDecision` approves only on a passed PR CI (`CiNotPassed` for `Pending` / `Failed` / `NotRun`), and a local-gate failure is a pre-filter rejection (`LocalGateFailed`), not a CI verdict; (2) the merge record names what it did not check — `Coverage::new` splits the workflow's jobs into `checked` / `unchecked` in workflow order and `record_names_unchecked` refuses a record that does not name every unchecked job; (3) a merge is refused while the target workflow is red on the base branch (`BaseBranchRed { failing_jobs }`, the failing jobs named) even when the local gate and the PR's own CI are green; (4) the gate's pass rate on the default branch is a reported number — `PassRate` carries the counters, renders `workflow on branch: N/M passed (P%)` via `line()`, and `all_failing` flags an all-failing gate (the 0/40 state) instead of smoothing it into "mostly passing". Regression tests (`crates/autospec-core/tests/merge_gate.rs`) reconstruct the incident — six jobs, three covered locally, a record naming nothing, a red base, 0/40 on `main` — and a full-coverage, green-base, 40/40 control that cannot see the defect.
