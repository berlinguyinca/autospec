### Added

- `autospec_core::gate_coverage`: a local gate is generated from the CI job's steps, and its pass states its coverage (issue #4304). The incident: a job named `"Rust baseline (fmt / clippy / test)"` runs 7 steps, an engineer transcribed the 3 named in the label into a local gate, and 4 steps were silently skipped while the gate reported "clean". Encodes the rules as checkable primitives: `derive_gate` (the gate is the job's `run:` steps in order, never anything parsed from the name) and `render_gate_script` (emits the gate with an `echo "gate step N/total: <name>"` line before each command, so coverage is in the artefact and not in the operator's memory); `coverage` with `Coverage` / `GateEquivalence` (a gate running a subset is `Partial { skipped }`, a gate running commands no CI step runs is `Divergent`, only the full set is `Same`); `Coverage::statement` (a pass renders `ran steps 1-3 of 7 (skipped 4-7)`, never "the gate is clean") and `Coverage::paired_lists` (the CI steps and gate commands side by side, each numbered); `format_step_ranges` (consecutive 1-based indices render as `1-3, 5, 7-8`, the empty set as `none`); `claim_from_words` with `GateClaim` (a pass claim is parsed into `RanSteps { ran, total }` or `GateIsClean`) and `challenge_claim` with `ClaimVerdict` ("the gate is clean" over a partial gate is `Overstated` with the correct restatement, a claim whose step numbers do not match the gate is `WrongCoverage` naming what actually ran, and only a claim matching coverage is `Accepted`); `name_policy` with `NamePolicy` (a job name may not enumerate steps at all — `PartialEnumeration { named, named_count, total_steps, not_listed, unbacked }` is a finding even when every token in the name is backed by a real step, because the harm is the omission a reader then runs, and `is_trap` says so; `GeneratedEnumeration` requires the name to match the steps exactly, `PurposeNamed` names nothing and is safe); `ArtifactContract` / `DriftCheck` (a contract declares the artifact, its pin file, the failure mode, the CI step indices that regenerate it, and the drift check — construction refuses an unnamed artifact, an empty failure mode, or a drift check with no command or rationale) and `artifact_drift` with `ArtifactDrift` (a gate that regenerates a committed artefact must carry the pin-file drift check in the same gate: `NotRegenerated` when no CI step regenerates it, `MissingCheck` when the contract declares no check, `CheckNotRun` when the gate omits it — naming the CI step that does run it — and `Covered` otherwise); and `audit` (the aggregate line for a clean gate is `OK: the gate is the CI gate`, otherwise every finding plus a `WARN: N finding(s)` summary). Tests: `crates/autospec-core/tests/gate_coverage.rs`.
