### Added

- `autospec_core::platform_gate`: platform-gate invariants for CI platform jobs (issue #4312). A platform-specific CI job (`macos-test`, `windows-test`, `freebsd-test`) is the sole verification of the code behind its `#[cfg]` gate, so when it goes red every line behind the gate merges unverified — the #4306 macOS breakage hid for a day and #4311 repeated the same shape on Windows. The module makes the invariants checkable: `classify_failure` maps a failing job to `CoverageLoss { job, platform }` when the job is the sole CI verification of a platform surface and to `Ordinary` otherwise, so a red platform job escalates as a total loss of coverage, never as a flaky check; `rate_alarm` fires when the gate's pass rate for the default branch is all-failing (0/N, N > 0) — conspicuous on its own, no state change required — and names the lost coverage, reusing `merge_gate::PassRate` rather than duplicating it (an empty window is unknown, not red); and `local_authority` scans a patch for `#[cfg(...)]` attributes and returns a `Hold` naming every surface the host cannot compile and the job that solely verifies it, so the converter's local gate defers to CI instead of authorising a merge it cannot verify. The predicate parser claims only what it can classify — `target_os`, `target_family`, the bare `unix`/`windows` families, and a single `not(...)` around them — and returns `None` for feature flags, `target_arch`, `any(...)`/`all(...)`, and unknown values: absence is the honest encoding, not an invented semantics. Tests: `crates/autospec-core/tests/platform_gate.rs`, including the regression that reconstructs the incident (an all-failing 0/40 rate, a red platform job, and a macOS-gated patch on a Linux host) and the control that a plain patch never holds.
