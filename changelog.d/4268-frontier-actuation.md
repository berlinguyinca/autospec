### Added

- `autospec_core::frontier_actuation`: actuation gaps — a loop that decides but cannot act (issue #4268). The frontier loop reported `8 ready, 0 dispatched` every pass: both numbers true, and together they hid the fact that dispatch was *impossible*, because dispatch requires a staged spec per issue and the producer of staged specs (`iw-stage.sh`) was a manual step outside the loop, run by whoever remembered to run it. An accurate-but-incomplete report reads as an idle loop when the state is a permanent stop. The module makes the three invariants checkable: (1) a loop that reports a decision must report whether it could act on it — `TickReport` carries the decided count (`ready`), the done count (`dispatched`) and every item in between with its reason, `TickReport::line` renders `N ready, M staged, K dispatched, X blocked: <reason>` with the blocked count grouped by distinct reason, `gap()` / `reconciles()` prove ready = dispatched + blocked, and `line_names_gap` refuses a line whose decided count differs from its done count without naming the gap and every reason behind it (the incident's line fails it, which is the point); (2) every precondition an actuator enforces needs a producer — `Precondition` pairs a `Guard` with the component that satisfies it, `Actuator::producerless` / `findings` / `FrontierLoop::preflight` list the guards that have none, and a guard with no producer is a `LoopVerdict::PermanentStop` naming its guard, not a safety check (`stop_line_names_guard` refuses a stop reported without its guard); (3) test the loop end to end against a real new item, not only the steady state — `FrontierLoop::tick` runs observe → decide → act and invokes the guard's producer before calling an item blocked, so staging happens in the loop rather than in someone's memory, while `stage` remains a refusal rather than a bypass (`StagingOutcome::Refused` below `MIN_STAGED_SPEC_BYTES`, reported as a block with `producerless: false`, distinct from a missing producer). Regression tests (`crates/autospec-core/tests/frontier_actuation.rs`) reconstruct the incident — eight dependency-closed issues, nothing staged, an unowned guard, the old line refused — and run the fix end to end: the same world plus a brand-new issue the loop stages and dispatches in its own pass, a too-short body refused rather than dispatched onto, and an idle pass that never renders as a stop.
