### Security

- T16 audit H3/H4: the review quorum is now on the merge path. New `autospec review-quorum merge-gate` (strict `verify-report`): `required` comes from the operator config and the default branch's `.autospec/autospec.yml` fetched fresh from the forge for the explicit `--repo` (never local `refs/remotes/*`, so `git update-ref` and a stale clone or odd default branch no longer drop the requirement; unreadable or missing means required), no stated policy means required (opt out only with `review_quorum: {required: false}` in a trusted config), a required quorum needs an attestation key or the live Herdr check, and the verified live head is returned as `merge_head`. `autospec-guarded-merge.sh` and the run-drain recovery merge call it and merge with `--match-head-commit`, refuse when `autospec` is missing or too old, and `autospec-promote-pr.sh` lost its legacy fallback. A refused merge or a moved head removes `autospec:verified` / `autospec:needs-human-review`. Operators with no `review_quorum` policy must now set one (or `required: false`) before the guarded merge will merge. Shell line counts do not rise.
- T16 review round 2: every merge path now runs the gate. The executor bridge calls the same Rust gate (strict, with its own `gh`) before `gh pr merge --match-head-commit`; the conductor roll-up promote in `autospec-loop.sh` and the spec-PR merges in `autospec-define` / `autospec-split` (+ codex/opencode copies) and the implementer contract go through `merge-gate` / `autospec-guarded-merge.sh`. `crates/autospec-cli/tests/bare_merge_ratchet.rs` fails when a new `gh pr merge` appears (ceilings in `tests/fixtures/bare-merge-allowlist.txt`). `merge-gate` exits 3 on a quorum refusal (the fence keeps 1; the run SKILL reports it as a quorum block), pins to the head read before classification or the caller's `--match-head-commit` and refuses if the live head differs, and requires `--script-version 2` (a stale script is told to run `install.sh --update`). Herdr enablement is read by one parser, ASCII-only trimming (`required: false<NBSP>` is not an opt-out), `HTTP 404` is matched exactly, `gh` calls are env-scrubbed, an explicit opt-out ignores a stray report, and an attestation key is refused only if tracked by an enclosing repository.
- T16 review round 3: a quorum refusal in the executor is now `InvariantNeedsHuman` (not retried 3 times; only a gh outage stays transient), and `merge-gate` exits 3 for a policy refusal and 4 for "could not determine, retry" (the guarded merge passes both through; the run and Phase 4 snippets share one handling and release the claim to needs-human). The trust anchor is no longer caller-chosen: release builds ignore `$HOME` and reject `--operator-config` / `--no-live` on `merge-gate`, and the wrapper dropped `--operator-config`. A trusted config with a tab, unbalanced brackets or trailing junk now means required, never an opt-out. `--match-head-commit=SHA` is normalised to one pin. New `autospec review-quorum config-check`, called by `install.sh`, warns loudly (no silent seeding) when no `review_quorum` policy is stated. The run-drain logs refusals. The bare-merge ratchet now also catches `gh api .../merge`, multi-space spellings and `--admin`, scans `docs/`, `tests/` and fixtures, and keeps separate executable and prose ceilings.
