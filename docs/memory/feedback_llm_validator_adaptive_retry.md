When designing any validator that gates LLM-generated content (issue
bodies, spec docs, PR descriptions, etc.) in the autospec family,
default to **adaptive retry with cumulative directive feedback**, not a
one-shot pass/fail gate.

**Why:** verbatim from user 2026-05-01, during Phase 2 refinement of
the issue-quality-gate spec:

> "remeber these are all generated by LLM's so when you lint/check for
> them, ensure you optimize the llm prompts until it gets it right"

A one-shot validator just labels failures; it doesn't *fix* them. The
LLM authoring the artifact gets no signal about how to recover. With
adaptive retry, each iteration accumulates findings into per-iteration
directives that the LLM can act on (`AVOID: bare verb 'improve'…`,
`COLLAPSE: smoke test must be one line, use && to chain…`).

**How to apply:**

1. **Default loop shape** for any LLM-output validator:
   ```
   MAX_RETRIES = 5
   accumulated_directives = []
   while attempt <= MAX_RETRIES:
       artifact = generate(base_prompt + accumulated_directives)
       findings = validator(artifact)
       if findings.empty: ship(artifact); break
       accumulated_directives += findings_to_directives(findings)
       attempt += 1
   else:
       surface_to_operator(artifact, all_findings)
   ```
2. **Findings-to-directives mapping** belongs in the spec doc as a
   table indexed by `RULE_ID`, so each rule has exactly one canonical
   LLM-actionable rephrasing. Worked example in
   `docs/specs/2026-05-01-autospec-issue-quality-gate-design.md` §5.
3. **Telemetry hint**: record `attempts: <K>` in the artifact's
   metadata (e.g. inside `<!-- autospec-quality:begin -->` markers).
   Rules that consistently take K≥3 attempts across many artifacts
   are signals to permanently amend the *base* generation prompt — a
   meta-improvement loop.
4. Cap `MAX_RETRIES` at 5. After that the staged context is wrong (too
   little, too vague, contradictory) and no amount of re-prompting
   will help — surface to operator with all drafts so they can split
   the work or fix manually.
5. **Post-filing audits** (Phase 3.5-shaped) are the *complement*, not
   the alternative — they catch artifacts that bypassed pre-filing
   (legacy, externally-filed, refined post-hoc) and label them for
   sweep. The pre-filing retry loop is the primary quality lever.

This principle compounds: every time the autospec family adds a new
LLM-output validator (decomposer-self-check, classify-rationale-check,
spec-section-presence-check, …), pair it with the same adaptive retry
shape so quality improves at generation time, not just at inspection
time.
