## 1. Goal

Reduce the per-invocation and on-disk token footprint of the 24-skill autospec
family without changing any loaded skill behavior, and pin the
deterministic-vs-LLM boundary for every pipeline touchpoint with
fixture-proven evidence instead of intuition.

## 5. Architecture

### D1 — Token baseline tooling (deterministic)
`scripts/skill-token-report.sh`: per skill → SKILL.md words → est. tokens
(words×1.33, integer) → duplicated-block share (% of words inside canonical
blocks). Emits a markdown table; `--json` emits machine-readable rows.
Committed report: `docs/reports/skill-token-baseline.md` (regenerated by the
script; staleness checked by comparing regenerated output in validate.sh —
warn-only).

### D2 — Canonical block templates + expander (single-source mechanism)
- `templates/skill-blocks/startup-self-update.md` (one `{{SKILL_NAME}}`
  parameter), `templates/skill-blocks/harness-adapter.md`,
  `templates/skill-blocks/dispatch-policy-row.md` — bodies copied verbatim
  from today's canonical text.
- `scripts/expand-skill-blocks.sh <file>`: replaces
  `<!-- autospec-block:<name> param=value -->` markers with the template body
  (param substitution is literal string replace of `{{KEY}}`; NO eval, NO
  shell expansion — counter-team injection guard). Idempotent on files
  without markers. Fails non-zero on unknown block name or missing template
  (fail closed).
- **Golden snapshots recorded BEFORE any conversion:**
  `tests/fixtures/skill-goldens/<skill>.SKILL.md.sha256` captured from
  current repo files. The new validate.sh gate `check_block_expansion`
  asserts: for every converted skill, `expand-skill-blocks.sh SKILL.md`
  output hash == golden hash. This PROVES loaded bytes are unchanged.
- `install.sh` pipes each skill file through the expander when markers are
  present (zero change for unconverted skills). `bootstrap.sh` flow is
  unchanged (it calls install.sh).
- Lockstep semantics after conversion: trio members carry IDENTICAL marker
  lines; `check_lockstep` continues to compare repo bodies (markers compare
  equal); `check_self_update`/`check_startup_preflight` are updated to accept
  EITHER the full canonical block OR its marker (transition-safe).

### D3 — Block conversion sweeps (mechanical)
Replace the duplicated blocks with markers across skills, one sweep child per
block class: (a) startup-self-update (20 skills × trio), (b) harness-adapter
table + dispatch-policy row (24 skills × trio). Mechanical-sweep precedent:
#1012. Each sweep's AC is the golden-hash gate going green for every touched
skill plus `autospec validate` exit 0.

### D4 — Quality-differential harness (the boilerplate guard)
`scripts/quality-differential.sh --step <name> --fixtures <dir>`: for a
determinized step, runs the deterministic path and compares against recorded
LLM golden outputs on ≥3 fixtures using per-step assertions (NOT string
equality — each fixture ships an `assert.sh` checking signal properties,
e.g. "output references ≥2 tokens from the input prompt", "no canned-string
markers"). Exit non-zero ⇒ the step must keep/restore its LLM path.
First consumer: refine lenses (expected: deterministic FAILS).

### D5 — Refine-lens inversion
Flip `scripts/refine-prompt.sh` lens dispatch to LLM-first (via the existing
`refine-prompt-lens-llm.sh` hatch) with deterministic template output used
ONLY as fallback when the LLM path is unavailable; tag artifacts
`degraded_fallback=true` in that case (existing field). Env hatch:
`AUTOSPEC_REFINE_LENS_MODE=deterministic|llm|auto` (default `auto` =
LLM-first). Keeps all six termination/convergence behaviors.

### D6 — Decision-table doc + inline-bash extraction
- Commit §4 as `docs/reports/llm-touchpoint-decision-table.md` with one
  fixture path per row (D4 fixtures; KEEP-LLM rows cite the fixture that
  justified keeping LLM — the refine-lens negative result).
- Extract the 5× repeated stop-sentinel bash fence in `skills/autospec` and
  `skills/autospec-run` SKILL.md bodies into a single shipped helper call
  (`${AUTOSPEC_SCRIPTS_DIR}/autospec-stop-check.sh "$ISSUE" "$BRANCH"
  "$LAST_STEP"`), shrinking loaded context. This DOES change loaded bytes —
  excluded from D2 golden gate; its own AC is behavior parity via the
  existing stop-mode bats suite.

> AUTONOMOUS ASSUMPTION: shrinking loaded SKILL.md bytes via D6 extraction is
> desirable (the AC "no SKILL.md grows" permits shrinking); only D2/D3 are
> bound to byte-identical loaded output.

## 6. Error handling

- Missing template / unknown marker → expander exits non-zero; install.sh
  aborts that skill's install loudly (fail closed, never installs a file with
  unexpanded markers); validate.sh gate red.
- Version skew (installed expander older than templates): install.sh runs the
  REPO copy of the expander from the fetched tree, never the installed copy.
- Golden mismatch → conversion child must fix the marker/template, never the
  golden (goldens change only with an explicit `docs:`-reviewed PR).
- Quality-differential failure → step keeps LLM path; report the failing
  fixture in the PR body.
