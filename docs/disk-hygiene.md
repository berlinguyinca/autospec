# Disk hygiene

Autospec worktrees, Rust `target/` dirs and test containers are the main disk
consumers on agent hosts. `scripts/disk-hygiene.sh` (installed to
`~/.autospec/scripts/`) is ON by default and works with or without
`herdr-eng` installed.

| Piece | Behaviour | Opt-out |
|---|---|---|
| Worktree cleanup | After a PR merges/closes, or a run fails/aborts, the worktree and its `target/` dir are removed when the tree is clean and its work is pushed. Otherwise it is kept and `disk_hygiene:worktree_kept` is logged. The path must be exactly a registered, unlocked linked-worktree root (never a subdirectory, the primary checkout or a `git worktree lock`ed tree). Prefers `herdr-eng cleanup --scope worktree --path <wt>` (detected with `herdr-eng cleanup --help`), falls back to `git worktree remove`; leftovers are swept only after git removal succeeded, never as a fallback after a failure. | `AUTOSPEC_DISK_CLEANUP=off` |
| "Pushed" | After a best-effort `git fetch --prune`, HEAD is pushed when it is reachable from its upstream (or, without an upstream, any remote), OR its PR is MERGED at exactly HEAD (needs `gh`), OR it is patch-equivalent to the default branch (`git cherry`). So squash-merged-and-deleted branches are reclaimed and stale remote refs do not hide lost work. | n/a |
| Ownership | `worktree-guard.sh create` writes its PID to `$WORKTREE_GUARD_CREATED_FILE` only when it really created the worktree. `dispatch-implementer.sh` and `explore-qa-gate.sh` clean up on abort only worktrees they created, never a reused or refused one. | n/a |
| Rust builds | `worktree-guard.sh create` (create and reuse) writes a git-excluded `.autospec-env.sh` exporting `CARGO_INCREMENTAL=0`. `CARGO_TARGET_DIR` is left alone: each worktree builds into its own `target/`, removed with it, so concurrent branches never overwrite each other's test binaries. | `AUTOSPEC_DISK_HYGIENE=off` |
| Docker | Test containers use `--rm --label herdr.ephemeral=1`; implementer prompts say so. | n/a |
| Disk pre-flight | Phase 4 dispatch, the autonomous drain and each conductor cycle check free space on the worktree, `$CARGO_TARGET_DIR` (if set) and `$HOME`. A path is low when free space is below min(`AUTOSPEC_DISK_MIN_FREE_GIB` (20 GiB), `AUTOSPEC_DISK_MIN_FREE_PCT` (10) % of the volume size): small volumes park before they are nearly full, big ones are not over-parked. It runs `herdr-eng cleanup`/`build-cleanup run` if available, re-checks, then exits 75 (`code_health:disk_low_parked`) so the issue is parked. A parked conductor cycle still writes its heartbeat, processes the control channel and counts toward `CONDUCTOR_MAX_CYCLES`, and sleeps at least `AUTOSPEC_DISK_PARK_SLEEP_SECS` (60). | `AUTOSPEC_DISK_PREFLIGHT=off` |
| Watchdog GC | An orphaned worktree is reclaimed when its heartbeat is stale and the issue is closed, gone or no longer labelled in-flight. Candidates are the linked worktrees that `git worktree list --porcelain` reports for the watchdog's own checkout (`AUTOSPEC_WATCHDOG_REPO_DIR`, default the cwd) under `$AUTOSPEC_WATCHDOG_GC_DIR/wt-*`, including the nested `/tmp/wt-feat/<name>` that `dispatch-implementer.sh` creates for a slash branch. The pass runs only when the checkout's `origin` names the watchdog's own repo (same host as `GH_HOST`, default github.com, and same owner/name); otherwise it logs `not this repo` and judges nothing. A worktree is judged only when autospec owns its branch: a heartbeat whose `branch` field names it, or the generated formats `feat/autonomous-issue-<N>` and `feat/<N>-<slug>`. Other branches (`release/2026-q4`, `fix/issue-12`, `explore-qa-gate-<PID>`) are left alone. Dirty means `git status --porcelain --untracked-files=all --ignore-submodules=none`, so `status.showUntrackedFiles=no` cannot hide a new file. A worktree that contains another registered worktree or any nested `.git` (for example an agent worktree under the ignored `.claude/worktrees/`) is kept as `nested_worktree`, even with `--force`. Order of checks: live heartbeat, then dirty / nested / unpushed (kept and logged before gh is asked), then the issue state. For an open, in-flight issue only a PR at exactly the worktree HEAD releases it: MERGED, or CLOSED plus `AUTOSPEC_WATCHDOG_GC_PR_CLOSED_GRACE_SECS` (3600) of worktree idleness. A transient gh error (network, auth, timeout) keeps the worktree and, in the main loop, the heartbeat; a definitive "issue not found" (deleted or transferred) counts as closed and the heartbeat and nudge state are removed. | Not switched off by `AUTOSPEC_DISK_HYGIENE=off` or `AUTOSPEC_DISK_CLEANUP=off`: those only stop `disk-hygiene.sh` doing the removal (the watchdog asks `disk-hygiene.sh cleanup-enabled`); the GC then keeps removing clean, pushed, closed-issue worktrees with its own plain `git worktree remove` (no `--force`, HEAD and cleanliness re-checked after the runtime teardown). There is no switch that stops the watchdog GC; stop the watchdog. |
| Bounded calls | Every gh, `git fetch` and ssh call in the watchdog and `disk-hygiene.sh` runs through `scripts/autospec-timeout.sh` (`timeout`/`gtimeout`, else a pure-bash background-job-and-kill fallback that also kills child processes), so one hung call cannot stop the watchdog. `git fetch` appends `-o BatchMode=yes -o ConnectTimeout=10` only for an OpenSSH ssh (`ssh.variant`/`GIT_SSH_VARIANT` = `ssh`, or auto with an `ssh` command); plink, putty and unknown wrappers are left as configured. | `AUTOSPEC_DISK_FETCH_TIMEOUT_SECS` (30), `AUTOSPEC_WATCHDOG_GC_GH_TIMEOUT_SECS` (30) |
| Everything in `disk-hygiene.sh` | Worktree cleanup, env, pre-flight. Not the watchdog GC (see above). `disk-hygiene.sh cleanup-enabled` exits 0 when cleanup is on and 1 when `AUTOSPEC_DISK_CLEANUP` or `AUTOSPEC_DISK_HYGIENE` is `off`. | `AUTOSPEC_DISK_HYGIENE=off` |

`AUTOSPEC_HERDR_ENG` overrides the `herdr-eng` binary name/path.

The installers copy `autospec-timeout.sh` and `disk-hygiene.sh` next to `autospec-watchdog.sh`. If the timeout helper is still missing, both scripts log a warning and run their commands without a time limit rather than failing every gh call. `AUTOSPEC_WATCHDOG_DRY_RUN=1` makes the watchdog skip every GitHub write (reclaim, nudge, run-state comment delete) while still reading; the test suite uses it so tests never mutate the real repository.
