# Design Pattern Decision

## Problem Shape

Describe whether the change is UI state, API integration, business rules, background work, validation, plugin behavior, report generation, data transformation, or AI/tool integration.

## Recommended Pattern

Use the smallest established pattern that makes the change reviewable.

## Acceptance Criteria

- [ ] Pattern rationale is documented.
- [ ] Existing local conventions are reused.
- [ ] Tests cover the behavior boundary.
