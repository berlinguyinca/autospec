Servers

Every machine reachable through this endpoint, and which models live on which GPUs. The plain /v1 is the balancer, so the default needs no configuration; each server also has its own base URL for when you want to insist.

Connect

An OpenAI-compatible endpoint. Pick a model, copy the snippet, and use a key from the Keys section. The base URL below is the balancer — it routes you to a machine that actually has the model you named, and the reply says which one.

Allow token headroom. These models emit reasoning before content, so max_tokens: 16 returns empty content — all of it went to reasoning. Either allow 512+ or send "chat_template_kwargs": {"enable_thinking": false}.

Where does it run? Every reply carries X-Routed-To, and consecutive requests stay on the same machine while its cache is warm — worth roughly tenfold on prompt processing. To pin one box instead, swap /v1 for /u/<server>/v1 from the Servers section.
Or generate the OpenCode config from the server, so client and server cannot drift: configure-opencode.py --presets /opt/qwen-turing/etc/router-presets.ini

Keys

Sign in to create keys that are yours: revocable on their own, with every request attributed to you. Machines carry keys; people sign in.

Usage

Who is using the node, ranked by tokens. Counts are exact — read from the model's own response rather than estimated — and cover everyone, because a scoreboard showing only your own row would not be one.

Health

Configuration problems the node can see in its own logs. Everything that is fine is hidden by default.
